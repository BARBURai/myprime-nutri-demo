# דף התשלום של מיי פריים

פרויקט נפרד מהאפליקציה. **הוא יושב באותו ריפו, אבל בוורסל הוא פרויקט משלו** עם
Root Directory = `pay`. כך תקלה בתשלומים לא נוגעת באפליקציה, והפונקציות שלו לא
נספרות בתקרה של 12 של האפליקציה.

כתובת לכל מוצר: `/<מוצר>`, למשל `/smart`. המוצרים, המחירים והטקסטים ב-`lib/products.js`.

## איך זה עובד
1. היא ממלאת פרטים בדף שלנו (`index.html`, `app.js`).
2. `api/create.js` שולח לקארדקום את הסכום **מהשרת**, ומקבל כתובת של טופס תשלום.
3. הטופס של קארדקום מוצג בתוך הדף. **פרטי האשראי לא עוברים דרכנו.**
4. בסוף, קארדקום מפנה את המסגרת ל-`done.html` (שמעביר את כל החלון לדף התודה)
   או ל-`fail.html` (שמבקש מהדף להציע ניסיון חוזר).
5. קארדקום מדווחת ל-`api/webhook.js`, שבודק מולה ב-GetLpResult ורק אז מכניס אותה
   לרשימה ברב מסר.
6. `api/sweep.js`, כל 10 דקות מ-cron-job.org: מי שלא שילמה תוך 30 דקות נכנסת
   לרשימת "רכישה נכשלה", פעם אחת.

## משתני סביבה בוורסל, כולם Sensitive ו-Production and Preview
| משתנה | מה |
|---|---|
| `CARDCOM_TERMINAL` | מספר המסוף. 1000 למסוף הבדיקות |
| `CARDCOM_API_NAME` | שם המשתמש לממשקים |
| `CARDCOM_MKT_FIELD_ID` | אופציונלי. מספר השדה "אישור קבלת דיוור" בקארדקום |
| `PAY_ORIGIN` | הכתובת של הפרויקט, למשל `https://pay.myprime.co.il` |
| `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` | להגנה מדיווח כפול ולרשימת "לא השלימה" |
| `RESPONDER_CLIENT_ID`, `RESPONDER_CLIENT_SECRET`, `RESPONDER_USER_TOKEN` | רב מסר |
| `PAY_SWEEP_SECRET` | הסיסמה שבכתובת של `api/sweep.js` |

## מה שעדיין לא אומת, כי הרשת של סביבת העבודה חוסמת את שני השרתים
- **רב מסר:** כתובת השרת והנתיב להוספת נמען לרשימה ב-`lib/responder.js`.
- **קארדקום:** הבקשה נבנתה לפי המדריך, ולא נשלחה עדיין למסוף הבדיקות.
- **מספרי רשימות התפוצה** ב-`lib/products.js` (`rmList`, `rmFailedList`).

## בדיקות
```bash
node qa/pay-check.mjs        # השרת, בלי רשת
node qa/e2e/pay.mjs          # הדף, בדפדפן אמיתי
```
