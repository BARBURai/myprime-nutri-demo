# MyPrime — AI QA harness (גרסה ראשונה)

אייג'נט QA אוטומטי לשכבת ה-AI של האפליקציה. הוא מייצר מטריצה רחבה של תרחישים (פרופילים × רגישויות × שבועות × סוגי בקשות, כולל מקרים עוינים), מריץ אותם **דרך אותם פרומפטים בדיוק** שהאפליקציה משתמשת בהם (`aiMealChat` להמלצות ו-`aiNutritionChat` להזנה), ומדרג כל תשובה מול רובריקה — בשילוב מדרג LLM נפרד והיוריסטיקת מילות-מפתח של אלרגנים.

> **מה זה לא:** זה בודק רק את שכבת ה-AI. דיוק נתוני המוצרים (FOODS מול מקור אמת) ובדיקות פונקציונליות/מכשירים הם תהליכים נפרדים. וגם: מדרג LLM אינו חף מטעויות — **חובה לעבור ידנית על כל הכשלים ועל מדגם מהעוברים**, במיוחד בבטיחות ואלרגיות.

## דרישות
- Node 18+ (משתמש ב-`fetch` המובנה, בלי תלויות).

## הרצה (מומלץ: מול ה-Deployment שלך)
זה הכי נאמן — בודק את המודל האמיתי שרץ אצלך, ולא צריך מפתח API בסקריפט (הפונקציה `/api/ai` כבר מחזיקה אותו):

```bash
QA_BASE_URL="https://<your-app>.vercel.app" node qa/run-qa.mjs
```

### אפשרות חלופית: ישירות מול Anthropic
```bash
ANTHROPIC_API_KEY="sk-ant-..." node qa/run-qa.mjs
```

## בדיקות תמונה (ניתוח צלחת)
בדיקת ניתוח תמונה דורשת **תמונות אמיתיות שאתה יודע מה בהן** (רק לך יש אותן). לכן:
1. שים תמונות צלחת בתיקייה `qa/images/`.
2. העתק את `qa/images/manifest.example.json` ל-`qa/images/manifest.json` ומלא לכל תמונה: `file`, `note` (תיאור), `expect` (מילות מפתח שאמורות להופיע בפריטים שזוהו), ו-`kcalRange` אופציונלי (טווח קלוריות כולל סביר).
3. הרץ כרגיל — האייג'נט יזהה את התמונות, ישלח אותן דרך אותו פרומפט של `analyzeMeal`, ויבדוק שזוהו הפריטים הצפויים ושסך הקלוריות בטווח, בנוסף לדירוג סבירות של ה-LLM.

אם אין `manifest.json`, בדיקות התמונה פשוט מדולגות (שאר ה-QA רץ כרגיל). `QA_IMAGES` מאפשר לשנות את נתיב התיקייה.

## משתני סביבה
| משתנה | ברירת מחדל | תיאור |
|---|---|---|
| `QA_BASE_URL` | — | בסיס ה-URL של האפליקציה הפרוסה. אם מוגדר — פונה ל-`${QA_BASE_URL}/api/ai`. **מומלץ.** |
| `ANTHROPIC_API_KEY` | — | מצב ישיר מול Anthropic (אם אין `QA_BASE_URL`). |
| `QA_MODEL` | `claude-sonnet-4-6` | מודל למצב ישיר (במצב `QA_BASE_URL` השרת דורס ממילא). |
| `QA_RUNS` | `2` | כמה פעמים להריץ כל תרחיש (ה-AI לא דטרמיניסטי). |
| `QA_LIMIT` | — | הגבלת מספר התרחישים (להרצת בדיקה מהירה). |
| `QA_CONCURRENCY` | `4` | בקשות במקביל. |
| `QA_OUT` | `qa` | תיקיית פלט לדוחות. |
| `QA_USER` | `qa` | קידומת המזהה שנשלח בכל בקשה. ראו "מכסת ה-AI" למטה. |

## מכסת ה-AI ⚠️
`api/ai.js` מגביל **30 פניות ליום ו-10 לדקה לכל משתמשת**, ובלי מזהה הוא סופר לפי
כתובת הרשת של מי שקורא. הרצה מלאה היא כ-336 פניות, כלומר בלי טיפול 30 היו עוברות
והשאר היו נחסמות. לכן כל תרחיש שולח מזהה משלו (`x-user-id: qa-<מזהה התרחיש>`),
וכל מזהה צורך 2 עד 4 פניות בלבד.

**שימו לב:** ההרצה מול הייצור נכנסת לדוח השימוש היומי ותיראה שם כקפיצה בעלויות
שאינה נשים אמיתיות.

## פלט
- `qa/report.html` — דוח קריא (RTL): סיכום, פילוח לפי קטגוריה, וטבלת כל הכשלים עם הפרומפט, התשובה, ונימוק המדרג.
- `qa/results.json` — כל הנתונים הגולמיים.

## חשוב על עלות
מספר הקריאות ≈ (תרחישים × `QA_RUNS`) × 2 (ייצור + דירוג). הסקריפט מדפיס את ההערכה לפני שהוא מתחיל. התחל עם `QA_LIMIT=20` כדי לוודא שהכל עובד, ואז הסר אותו לריצה רחבה.

## לשמור מסונכרן ⚠️
הפרומפטים של `aiMealChat`/`aiNutritionChat` והרכבת ה-seed הועתקו מילה-במילה מ-`src/App.jsx`. **אם משנים אותם ב-App.jsx — צריך לעדכן גם כאן** (מסומן בקובץ ב-`KEEP IN SYNC`).

**זה כבר קרה.** מ-v4.44 מסך ההמלצות מחזיר אופציות מובנות, וההעתק כאן המשיך לבקש טקסט
חופשי עד 10 באוגוסט 2026. הרצה במצב כזה בודקת אפליקציה שלא קיימת ומחזירה רשימת כשלים
מדומים. לכן יש עכשיו שומר, והוא חייב לרוץ לפני כל הרצה:

```bash
node qa/prompt-sync-check.mjs
```

# שכבה 1: דיוק נתוני מזון

בדיקות שרצות **בלי רשת ובלי קריאות AI**, כלומר בחינם ובכל רגע. אלה משלימות את
האייג'נט שלמעלה, שבודק את שכבת ה-AI ולא את הנתונים הקבועים.

```bash
node qa/food-check.mjs           # טבלת המזונות הקבועה באפליקציה
node qa/barcode-guard-check.mjs  # ההגנה על נתונים מברקוד
node qa/prompt-sync-check.mjs    # ההנחיות כאן מול ההנחיות באפליקציה
node qa/meal-options-check.mjs   # קריאת האופציות של מסך ההמלצות
```

**`food-check.mjs`** קורא את טבלת 34 המזונות מתוך `src/App.jsx` ובודק שני דברים
שלא דורשים מקור חיצוני ולא דורשים שיקול דעת:

1. **קלוריות מול מאקרו.** הקלוריות אינן מספר עצמאי אלא נגזרות מהמאקרו: 4 קלוריות
   לגרם חלבון, 9 לגרם שומן, 4 לגרם פחמימה. שורה שבה הקלוריות הרשומות לא מסתדרות
   עם המאקרו של עצמה שגויה באחד משני המספרים. סיבים תזונתיים ואלכוהול מטים את
   החישוב, ולכן רק פער גדול נחשב לממצא.
2. **מסה ומידות.** חלבון ושומן ופחמימה לא יכולים לעבור 100 גרם בתוך 100 גרם, וכל
   מידה ביתית חייבת להיות משקל הגיוני.

**`prompt-sync-check.mjs`** משווה את ההנחיות שבקובץ הזה מול `src/App.jsx`, ומחלץ מכל אזור
את תוכן המחרוזות בלבד, בלי שמות משתנים ובלי הערות. כל שינוי בנוסח באפליקציה מפיל אותה
מיד ומצביע על המשפט עצמו.

**`meal-options-check.mjs`** בודק את קריאת האופציות של מסך ההמלצות: תשובה חתוכה שממנה
עדיין צריך לחלץ אופציות, תשובה בלי אופציות בכלל שחייבת להיתפס כתקלה, **והכלל שהחלבון
מוצג רק משבוע 3.** בלי הכלל האחרון כל תרחיש של "בלי מאקרו לפני שבוע 3" היה נכשל על
שדות שהאישה לא רואה על המסך.

**`barcode-guard-check.mjs`** מריץ את `nutritionPlausible` מתוך `src/App.jsx` מול
מוצרים תקינים ומול שורות פגומות. Open Food Facts הוא מאגר שמשתמשים ממלאים,
והפונקציה הזאת מחליטה אם להציג את המוצר או לבקש ממנה לצלם את התווית, כלומר
**מה שהיא מפספסת נרשם ליומן כאילו הוא נכון.**

## מה עדיין לא נבדק

השוואה מול מאגר משרד הבריאות ("צמרת") ובדיקת פענוח העמודות ב-`api/il-food.js`
דורשות גישה לרשת שלא קיימת בסביבת הפיתוח הזאת. אלה נשארות פתוחות.
